# CFR paired reconstruction benchmark

Status: measurement, 2026-09-19. The controlled benchmark for
[the reconstruction pilot](closing-the-gaps-2026-09-19.md) §3: hide the XML of
a published CFR section, reconstruct it from the section PDF, and score the
result against the XML that was hidden.

The CFR is a benchmark and **not** the deployment corpus. Every annual edition
GovInfo serves has XML, so a production pipeline would retrieve that XML and
never reconstruct it — which is precisely what makes this corpus worth
running: it is the only one in reach where the right answer is published. The
deployment corpus, pre-113th bill text, has no reference at all, and a
pipeline that cannot be scored where a reference exists should not be pointed
at a corpus where none does.

## How to reproduce

```sh
uv run --frozen python -m tools.analysis.reconstruction_benchmark \
    --env-file .env --sections 40 \
    --output docs/research/reconstruction-benchmark-2026-09-19.json \
    --report docs/research/reconstruction-benchmark-2026-09-19.md

# Re-render the generated block from the saved sidecar, no network:
uv run --frozen python -m tools.analysis.reconstruction_benchmark --offline \
    --output docs/research/reconstruction-benchmark-2026-09-19.json \
    --report docs/research/reconstruction-benchmark-2026-09-19.md
```

The credential is read with `read_api_key(Path(".env"), "API_GOV")` and
travels only in the `X-Api-Key` header, on the one keyed route the run uses
(the granule listing). Both body routes are keyless. Fetched bodies land in a
scratch directory outside this repository; the sidecar keeps each one's URL,
byte size and SHA-256, so a rerun can prove it fetched the same bytes without
the repository carrying them.

## What the measurement cannot see

- **One volume per edition.** The corpus is four (year, title, volume)
  editions with sections taken at an even stride through each volume's
  granule listing. A title whose typography differs from these four could
  behave differently, and sections within one volume are far from
  independent — which is why the splits are whole editions and why the
  per-edition table below is reported beside the total.
- **A reference that is itself a rendition.** The score is against GPO's own
  XML conversion of the same SGML. Where the print and the XML disagree, this
  reports a discrepancy without deciding which is right.
- **A section PDF is a page range.** It routinely carries the end of the
  previous section and the start of the next. That material is counted as
  out-of-scope evidence, never as loss; the "Sections in PDF" column says how
  many section headings each rendition actually contained.
- **A clean run is not a coverage claim.** At a one-sided 95% bound, forty
  clean documents still permit roughly a 7% error rate (a hundred permit 3%),
  so the audit grows with the claim.
- **The blind split was spent during development, and its numbers are
  development numbers.** Seven rules and repairs were derived while this
  corpus was being read; the sidecar's `splitIntegrity` field names every
  granule whose evidence shaped one and the split it landed in, so the
  caveat is data rather than prose. Four are in the blind split:
  `CFR-2022-title40-vol1-sec23-2` (`small_caps_restore`,
  `small_caps_continuation`), `CFR-2023-title7-vol1-sec3-52`
  (`gpo_quote_pair`), `CFR-2023-title7-vol1-sec1-313` (`print_shop_footer`
  and the subject-continuation join) and `CFR-2023-title7-vol1-sec15-86`
  (which motivated the deliberate *refusal* to write a
  subject-group-heading rule). Two are in tuning (`CFR-2024-title12-vol1-sec28-5`
  for `division_heading`, `CFR-2024-title12-vol1-sec1-1` for the
  compound-hyphen join) and one in development
  (`CFR-2025-title30-vol3-sec700-1`). The split machinery is real — whole
  editions, no volume on two sides — but it can only start paying on a run
  that draws editions this one never touched and changes no rule while it
  reads them. Until that run, the honest reading of every number below is
  "this is how the rules do on the corpus they were written against."

## Reading the findings

The five checks are separate findings on purpose
([`reconstruction/validate.py`](../../src/spicy_docs/reconstruction/validate.py)),
because they fail for different reasons: schema validity is a serializer
question, content fidelity an extraction-and-join question, structural
fidelity a parser question, and coverage honest ignorance. Acceptance is a
pure function over the other four and refuses to pass a gate it could not
decide.

## What the nine unaccepted documents actually are

Every document that fell short is one of four things, and none of them is
lost text:

1. **A paragraph designation set run-in after an italic heading** (4 of 9).
   GPO prints `(e) *Variances from …requirements.* (1) This section applies…`
   as one paragraph, so the `(1)` never begins a line and the print gives the
   parser nothing to place it by. It flags the next designation as out of
   sequence and marks the node `needs_review` rather than guessing — which is
   what the 70% "accepted without review" gate is for. The published XML has
   the same shape, so the text and the ladder both still score 1.000 on these
   documents; what is unresolved is a *marker*, exactly the class §3.3 says
   must never pass unresolved.
2. **An en dash where the XML has a hyphen** (2 of 9,
   `CFR-2022-title40-vol1-sec35-101` and `CFR-2025-title30-vol3-sec700-1`).
   The print sets `Pub. L. 95–87`, `104–134`, `1321–299` and `105–65`; the
   XML spells them with a hyphen. The comparison keeps em and en dashes
   deliberately, and the critical class this run re-scored with sees both
   spellings: 8 critical tokens on these two documents, where the class it
   replaced could see only whichever rendition held the hyphen — 4 critical tokens in one spelling (one document had three, the other one). The same
   two documents either way; what changed is that the count is no longer a
   lower bound built from one spelling. This is a disagreement between two
   renditions of one document, not a reconstruction error, and it is
   reported without deciding which rendition is right.
3. **A centred small-capital subject-group heading read as a section
   heading** (1 of 9, `CFR-2023-title7-vol1-sec15-86`). GPO sets an
   undesignated group head — `HEARING OFFICER` — centred, in the body face,
   in small capitals. The parser has no rule for it, so it lands inside the
   section above it and adds two tokens. **This is the one genuine parser gap
   the run found**, and the rule it needs (a centred, wholly small-capital
   body-face line is a subject-group heading that closes the section) is
   deliberately *not* added here: it would be another rule derived from a
   document in the blind split, and the split has already been spent once.
   It belongs in the next run, written before that run's corpus is drawn.

4. **A section the page range may have cut short** (2 of 9,
   `CFR-2024-title12-vol1-sec3-155`, `CFR-2024-title12-vol1-sec9-6`). Each
   carries exactly one in-scope node flagged `needs_review`: the requested
   section ends at the rendition's last line, so its text may continue on a
   page this granule does not contain (`section_truncated`). The gate this
   run replaced counted both documents "accepted" because it never read the
   review flags; the reworked one holds them for review, which is what
   "accepted **without review**" has to mean.
